# Security Policy

## Supported Versions

Only the latest release receives security fixes.

| Version | Supported |
|---------|-----------|
| Latest  | ✅        |
| Older   | ❌        |

## Reporting a Vulnerability

**Please do not open a public GitHub issue for security vulnerabilities.**

You have two options:

1. **GitHub Private Security Advisory** (preferred)
   Navigate to the repository → **Security** → **Advisories** → **Report a vulnerability**.

2. **Email**
   Send details to the maintainer's email listed in the repository profile.
   Use the subject line: `[CommitForge] Security Vulnerability Report`.

### What to include

- A clear description of the vulnerability and its potential impact
- Steps to reproduce or a proof-of-concept
- Affected versions (if known)
- Any suggested mitigations

### Response timeline

| Stage                        | Target   |
|------------------------------|----------|
| Initial acknowledgement      | 48 hours |
| Triage and severity decision | 5 days   |
| Fix or mitigation published  | 30 days  |

We will coordinate disclosure timing with you and credit you in the release notes
unless you prefer to remain anonymous.
